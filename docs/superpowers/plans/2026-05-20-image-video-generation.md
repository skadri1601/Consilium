# Image & Video Generation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Allow Consilium debates to produce images and short videos in addition to text. The use case: design reviews ("debate three logo concepts"), product mocks ("generate a hero image for each take"), training-data debates ("compare DALL-E vs Imagen on this prompt"). Route image/video prompts to provider tools (DALL-E 3, Imagen 4, Veo 4), save artifacts under `~/.consilium/generated/`, and reference them in the debate transcript.

**Architecture:** A new media-generation tool, exposed to the council via the MCP tool bridge. When the orchestrator detects that a council member's response contains a `generate_image` or `generate_video` tool call, the engine dispatches it to the appropriate provider, persists the binary to a CDN-backed bucket, returns the URL to the model, and emits a `media:generated` SSE event so the CLI can download + show the file.

**Tech Stack:** OpenAI Images API (DALL-E 3, gpt-image-1), Google Vertex AI (Imagen 4, Veo 4), Stability AI (SDXL 1.5) as the cheap fallback. Storage on Cloudflare R2 with a public signed-URL bucket. CLI rendering with `terminal-image` (sixel/Kitty graphics protocol when supported, ASCII fallback).

### Task 1: Backend Tool Definition

**Files:**
- Create: `apps/agents/src/features/tools/media_generation.py`
- Modify: `apps/agents/src/features/deliberation/tool_dispatcher.py`

- [ ] **Step 1: Tool schema** with two tools: `generate_image(prompt, style?, aspect_ratio?, count?)` and `generate_video(prompt, duration_sec?, aspect_ratio?)`. Counts capped at 4 images and 1 video per debate by default.
- [ ] **Step 2: Provider router** picks a provider from a preference list: image defaults to OpenAI, video defaults to Veo. Falls back to Stability if the requested provider's quota is exhausted.
- [ ] **Step 3: Cost gate** uses the `BudgetGuard` if `max_budget_usd` is set in the debate; refuses to generate when the running tally would exceed it.
- [ ] **Step 4: Tool dispatcher wiring** so the dispatcher resolves `generate_image` and `generate_video` to this module's handler.

### Task 3: Storage + Signed URLs

Generated bytes go to R2 (S3-compatible). The URL returned to the model and the CLI is a short-lived signed URL so the artifact isn't world-readable forever.

**Files:**
- Create: `apps/agents/src/features/tools/storage/r2_uploader.py`

- [ ] **Step 1: R2 client** with credentials from `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY`. Bucket name from `R2_MEDIA_BUCKET`.
- [ ] **Step 2: Upload + sign** uploads to `debates/<debateId>/<uuid>.<ext>`; returns a 7-day signed URL.
- [ ] **Step 3: Garbage collection job** weekly: delete artifacts whose debate is older than 30 days unless the user pinned them. (Pinning UI is out of scope; document the pin flag in DB schema.)
- [ ] **Step 4: Tests** mock S3 with `moto`.

## Acceptance criteria

1. A debate with prompt "Compare three landing page hero concepts" yields three generated images, each saved under `~/.consilium/generated/<debateId>/` with the prompt embedded in the filename.
2. CLI renders inline previews on Kitty + iTerm2; falls back gracefully on plain terminals.
3. Web shows each artifact inline with the model's argument; click for fullscreen.
4. Budget guard refuses to generate when the running cost would exceed `--max-budget-usd`.
5. R2 signed URLs expire in 7 days; expired URLs return 403.
6. Total backend latency for a single DALL-E call under 8s in p95.

## Out of scope

- Image editing / inpainting (separate plan).
- Video longer than 10s (Veo's hard cap at SDK ship).
- Custom model fine-tunes per user (uses platform-hosted models only).
- Local generation via Stable Diffusion (`stable-diffusion-cpp`) — design only; punted to Phase 2.
- Aspect ratios beyond the providers' built-in sets.

## Estimated effort

4 engineer-weeks: 1.5 weeks backend (tool + 4 providers + storage), 1 week SSE wiring + shared types, 1 week CLI + web rendering, 0.5 weeks tests + cost integration.
